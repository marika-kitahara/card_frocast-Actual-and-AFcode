============================================================
1. アプリの目的
============================================================
申込・発行の2種類のAFコード別日次実績を、AFマスタとAFFマスタで領域・割り振りに対応付け、指定期間の領域別サマリ、割り振り別日次実績、ローデータを1つのExcelにまとめるStreamlitアプリ。
出力は「サマリ」「申込_実績」「発行_実績」「ローデータ」の4シート。

============================================================
2. 利用手順
============================================================
(1) Streamlitアプリを開く。
(2) 「AFマスタ」「AFFマスタ」「申込データ」「発行データ」のxlsxを各枠にアップロードする。4ファイルすべて必須。
(3) 申込・発行データの日付を基に表示される「期間選択」で開始日・終了日を指定する。初期値はデータの最新日が属する月の1日～最新日。
(4) 画面の「サマリ（領域別）」で申込・発行の表を確認する。
(5) 「集計結果をダウンロード（Excel）」を押して保存する。
出力ファイル名：実績集計結果_YYYYMMDD_YYYYMMDD.xlsx（指定した開始日・終了日）。
※処理は期間選択後に自動実行。別途「集計開始」ボタンはない。

============================================================
3. 入力ファイルの仕様
============================================================
【AFマスタ／xlsx】
・Excel内で「AFコード」という文字列を含む行をヘッダー行として自動検出（先頭シート）。
・必要列名：「AFコード」「割り振り」「領域」。列名とコード・割り振りの半角／全角スペースは除去する。
・「領域」列の値自体はread_af_master内で正規化していない（後段のサマリで領域名を正規化）。
・注意：ヘッダーが見つからない場合、最初の行をヘッダーと誤認する可能性がある。列が欠けると読み込みエラー。

【AFFマスタ／xlsx】
・先頭シートの1行目をヘッダーとしてpd.read_excelで読み込む。
・データ列は厳密に2列であることが前提。読み込み後、列名を位置順に「AFコード」「領域」に置き換える。
・「割り振り」はAFコードと同じ値に設定する。
・余計な列があると列名の設定時にエラーとなる。

【申込データ・発行データ／各xlsx】
・先頭シートの1行目がヘッダー、2行目以降が日別実績。
・先頭列が日付（列名は何でもよい。読み込み後「日付」に改名）。日付は原則 YYYYMMDD の8桁数値（例：20261101）。
・2列目以降の列見出しがAFコード、各セルが該当日の実績値。
・日付は int に変換後、先頭4桁を年、次2桁を月、次2桁を日として変換する。Excelの日付型、YYYY/MM/DD文字列などは正しく扱えない可能性がある。
・日付変換に失敗した行は除外。申込・発行の両方に有効日付がない場合は処理停止。
・空欄または0の実績は読み飛ばす。AFマスタ／AFFマスタに存在しないコードも集計対象外（DM例外あり）。
・実績値は数値を前提とする。文字列混入はgroupby集計で問題になる可能性がある。

【画面内マスタ参照リンク】

============================================================
4. データの突合・集計ロジック
============================================================
① AFマスタ→AFFマスタの順で縦結合。
② AFコードが空の行を除き、AFコードの重複は先頭1件だけ残す。このため同一コードが両マスタにある場合、AFマスタの定義を優先する。
③ 実績ファイルの各日付・各AFコード列を走査。指定期間外、空欄、0は除外。
④ 特別扱いするDMコードは以下の4件：MCS056／APD023／GEZ039／STD002。
　これらはマスタ上の定義よりもDM判定を優先し、「割り振り＝元のAFコード」「領域＝DM」で計上する。
⑤ DM以外はマスタに該当コードがある場合のみ「割り振り」「領域」を採用する。該当しないコードは出力に含まれない。
⑥ 「種別（申込・発行）×日付×割り振り×領域」で実績を合算する。
⑦ 領域別サマリは「領域×日付」で集計し、Affiliate／Listing／Display／DMの順に並べる。該当しない領域も0行として表示。その他の領域名は末尾に追加。
⑧ 領域名はサマリ作成時に前後・内部スペースを除去し、大文字小文字を無視して上記4名称に寄せる。
⑨ 領域別サマリには行方向の合計「total」列、列方向の合計「total」行を追加する。
⑩ 申込_実績・発行_実績は「日付×割り振り」のピボット表。領域を区別せず同じ割り振りの数値を合算し、右端に「total」列を付ける。

============================================================
5. Excel出力仕様
============================================================
ファイル名：実績集計結果_開始日_終了日.xlsx
・サマリ：申込表と発行表を縦に配置。各表は領域を行、日付を列とし、「total」行・列あり。
・申込_実績：日付を行、割り振りを列とする申込実績表。日付は YYYY/MM/DD 表示、total列あり。
・発行_実績：同形式の発行実績表。
・ローデータ：種別／日付／割り振り／領域／実績の5列。日付は YYYY/MM/DD 文字列。
・出力にはxlsxwriterを使用。罫線・色などの追加書式設定は行っていない。

============================================================
6. 実装ファイル・ライブラリ・主な関数
============================================================
・アプリ本体：アップロードされたPythonソースを app.py として配置する想定。
・必要ライブラリ：streamlit、pandas、openpyxl（Excel読み込み）、xlsxwriter（Excel書き出し）。
・起動例：streamlit run app.py
・requirements.txtの例：
  streamlit
  pandas
  openpyxl
  XlsxWriter

主な処理：
normalize：スペース除去・欠損値の空文字化
convert_date：YYYYMMDD数値を日付に変換
read_af_master：AFマスタのヘッダー検出・必要列抽出
read_aff_master：AFFマスタ2列の読み込み・割り振り設定
process_raw：AFコード照合、DM特例、期間抽出、種別×日付×割り振り×領域集計
create_actual_block：割り振り別の日次実績表作成
ensure_area_rows：領域名の正規化と表示順の固定
make_summary_df：領域別サマリに合計行・列を付与
to_excel：4シートのExcelをBytesIOに書き出す

7. 保守時に変更する箇所
============================================================
・DMとして扱うコードの追加・削除：冒頭の DM_CODES。
・領域の表示順：AREA_ORDER。
・領域名の揺れ対応：AREA_NAME_MAP と ensure_area_rows。
・AFマスタの列名や構造変更：read_af_master。
・AFFマスタの列構造変更：read_aff_master。
・実績ファイルの日付形式変更：convert_date と申込・発行読み込み部分。
・突合ルールやマスタ優先順位変更：process_raw。
・出力シート構成／レイアウト変更：to_excel。
・ダウンロード名変更：末尾の st.download_button。

8. 注意事項・既知のリスク
============================================================
(1) マスタに存在しないAFコードは警告なく集計から消える。出力合計と元データ合計が一致しない場合、未登録コードを確認すること。
(2) 同じAFコードのマスタ定義はAFマスタ側が優先。重複定義の不一致は警告しない。
(3) DM_CODESの4件はマスタに登録がなくても集計され、DMとして扱われる。
(4) 「割り振り」が空欄のマスタ行でも、コードが一致すれば空欄の割り振りとして集計され得る。
(5) 日付の解析は8桁数値前提。Excelシリアル日付・datetime形式等は変換失敗や誤変換の可能性がある。
(6) 全期間で対象実績が0件となる場合、空のピボット表に対してtotal列の処理が行われるため、エラーになる可能性がある。空データの扱いは未検証。
(7) 「領域」の正規化はサマリ側だけ。ローデータの領域表記には元マスタ由来の揺れが残る可能性がある。
(8) 同じ日付・同じ割り振りが複数領域にまたがる場合、申込_実績／発行_実績では合算される。領域別の内訳はサマリ／ローデータで確認。
(9) Excelファイルの先頭シートを読み込む仕様。目的のデータが別シートにある場合は事前に整理する。
(10) AFマスタのヘッダー検出は「AFコード」を含む最初の行を採用する方式。説明行などに同語がある場合は誤認に注意。
(11) 期間選択の開始日・終了日は両端を含む。画面初期値はアップロードデータの最新日が属する月の初日から最新日まで。
(12) 例外処理があるのはマスタ読み込み部分など一部。実績ファイルの形式不備によってはStreamlitにエラーが直接表示される。

9. 引き継ぎ時の動作確認チェックリスト
============================================================
□ 4種類のExcelをアップロードし、期間選択・サマリ表示・Excel保存が完了する。
□ 申込・発行それぞれの期間内の日次合計を手集計し、サマリのtotalと一致する。
□ Affiliate／Listing／Display／DMの表示順と0件領域の表示を確認する。
□ DM特例4コードが必ずDMに入ることを確認する。
□ AFマスタとAFFマスタに重複コードを用意し、AFマスタ優先になることを確認する。
□ マスタ未登録コードの除外を確認し、元データとの差分を把握する。
□ 申込_実績／発行_実績の割り振り別数値とローデータの集計が一致する。
□ 開始日・終了日当日の数値が含まれることを確認する。
□ 期間内に対象データがない場合の挙動を確認する。
□ 出力Excel4シートの列・日付・total行列を確認する。
□ Boxのマスタ参照リンクと閲覧権限を確認する。
